### 结果
`scripts/test/Fbank.py`（用户手写）初版与 torchaudio 差 **rel 139% / mean 1.45**（特征范围才 [-23.0, 4.3]）；
修正后 **`torch.equal == True`，559×80 = 44720 个数值零误差**；边界扫描 **20/20 bit-exact**
（2 段音频 × {80/40/23/64 mel、snip_edges=False、去DC关、400fft、20ms/5ms 帧、low_freq=0/40、8k 重采样}）。

### 三处根因（按严重度）
1. 🔴 **mel 滤波器组在 bin 索引域插值（方法性错误）**：先把 mel 端点 `floor` 量化成 bin 索引再插值，
   而低频相邻端点间距仅 ~23 Hz、400 点 FFT bin 宽 40 Hz → **5 个 mel bin 整行塌陷为 0**
   （索引 `[0,2,5,9,14]`，与端到端误差最大的 5 个 bin **完全重合**，因果链闭合）。
   正解（Kaldi 做法）：把**每个 FFT bin 的中心频率**转成 mel 值，再
   `clamp(min(up_slope, down_slope), min=0)` —— 不再需要 `if left < center` 的整型边界判断。
2. 🔴 **FFT 点数 400 → 512**（Kaldi `round_to_power_of_two` 零填充），bin 宽 40 → **31.25 Hz**；
   mel banks 按 512 生成（256 列）后右补一列 0 对齐 Nyquist。
3. 🟡 **顺序错 + 缺去直流**：Kaldi 真实顺序是 **先分帧 → 每帧减均值 → 帧内预加重 → 加窗**；
   用户原版是"整段波形预加重 → 再分帧"，且首样本应为 `x[0]-0.97·x[0]=0.03·x[0]`（replicate 填充所致），
   非"直接保留 x[0]"。log 下限应为 `eps(float32)≈1.19e-7`（原用 1e-10）。

### 权威实现要点（已从 `torchaudio/compliance/kaldi.py` 源码逐行核对，非凭记忆）
- `fbank()` **没有** `waveform * (1<<15)` 缩放（老版本有，本版 2.11.0 无）——踩过这个怀疑。

- `spectrogram()` 与 `fbank()` 唯一区别：前者把 `power_spectrum[:,0]` 换成 `signal_log_energy`。

1. 🔴 **`blank_idx = C-1` 硬编码** —— `torch.nn.CTCLoss` 默认 `blank=0`。两者混用会「看起来完全正确、结果全错」

### ★★ Bug 2（严重且很有教学价值）：**`dp[i]` 存整段序列 → 最坏时间 O(n³)**

`vector<vector<ll>> dp` 存的是**整个序列**而不是**长度**。每次"发现更优"就 `dp[i]=dp[j]` **整段拷贝**。
单调递增输入下总拷贝元素数 = Σ_k k²/2 ≈ **n³/6**。

实测（单调递增，DP 内部计时）：
| n | DP 耗时 | 倍率 |
|---|---|---|
| 1000 | 20.1 ms | — |
| 2000 | 190.8 ms | 9.5× |
| 4000 | 3874 ms | 20.3× |
| 8000 | **33906 ms** | 8.8× |

**规模 8 倍 → 耗时 1685 倍**（O(n²) 只该涨 64 倍）。对照：同样 n=4000 的**随机**输入只要 19.6 ms，
即被卡时慢 **200 倍以上**。空间最坏 n(n+1)/2 → n=8000 时 256 MB、n=20000 时 1.6 GB。

→ **这条是可复用的教学点：DP 状态存"值"还是存"整条路径"，会把 O(n²) 变成 O(n³)。**

### build.py 的设计缺陷（已修）
脚本自己的横幅/耗时/编译命令原本 `print` 到 **stdout**，会污染被测程序的输出 ——
想 `build.py xxx.cpp > out.txt` 对比答案就不行。
→ 现在：**脚本信息全部走 stderr**（新增 `say()` helper），
**被测程序 stdout 用 `sys.stdout.buffer.write` 原始字节透传**。

变成 `\r\r\n`（实测踩到过）。用 `buffer.write(bytes)` 才是字节精确的。
