# P01｜最长递增子序列（LIS）

| 项 | 内容 |
|---|---|
| 难度 | **中等**（LeetCode 300 的加强版） |
| 考点 | 动态规划、二分查找、**贪心 + 决策单调性**、路径还原 |
| 为什么选这题 | 昨天（D1 任务 6）你练了 `lower_bound` / `upper_bound`。**这题的正解就是它唯一的实战用法**——练完立刻能用上，不是白练 |
| 岗位映射 | 语音/大模型岗手撕题高频；「路径还原」直接对应 CTC/Viterbi 里的回溯 |
| 预计耗时 | 90–120 分钟 |

---

## 一、题目

给定一个长度为 `n` 的整数数组 `a`，求它的**最长严格递增子序列**（LIS）。

「子序列」指数组中**不要求连续**、但保持原有先后顺序的一段元素。

**输出三样东西：**
1. LIS 的**长度**
2. **一条**具体的最长递增子序列（有多条时输出任意一条即可）
3. 两种解法的**运行耗时对比**

---

## 二、输入输出格式

**输入**（stdin）
```
第一行：n            (1 <= n <= 200000)
第二行：n 个整数 a[i]  (-10^9 <= a[i] <= 10^9)
```

**输出**（stdout）
```
第一行：LIS 长度，例如  4
第二行：一条 LIS，空格分隔，例如  2 3 7 101
```

> 之所以要求输出「具体序列」而不是只输出长度：**只输出长度的话，你写错了也不一定看得出来**
> （长度对了可能是巧合）。而且回溯路径是 CTC beam search、Viterbi、对齐算法里的必备技能。

---

## 三、样例

**样例 1**
```
输入

输出
4
2 3 7 101        （或 2 3 7 18，都对）
```

**样例 2**
```
输入

输出

```

## 四、任务分解（三问，按顺序做）

### 第 1 问：`O(n²)` 动态规划 —— 先把「对」做出来

定义状态、写出转移、拿到正确答案。这一问不追求效率，**只求你能把状态定义讲清楚**
（面试第一问通常就是这个）。

要求：在代码里写出 `lis_length_dp()`，并在注释里用一行说清 `dp[i]` 的定义。

---

### 第 2 问：`O(n log n)` —— 这题的正解

把复杂度降到 `O(n log n)`。**提示只有一句：正解要用到二分查找。**

做完之后必须能回答下面两个追问（写在注释里）：

> **追问 A**：你用的是 `lower_bound`（第一个 `>= x`）还是 `upper_bound`（第一个 `> x`）？
> 能不能说清**为什么**是它？
>
> **追问 B**：如果题目改成「**非严格**递增」（允许相等，即求最长**不下降**子序列），
> 二分该换成哪个？改一个词就够，但你要能解释清楚**为什么换**。

> 💡 这两个追问是这道题真正的考点。很多人能背出 `O(n log n)` 的写法，
> 但被问「为什么不是另一个二分」就卡住——那说明只是背下来了。

---

### 第 3 问：还原出**一条**具体的最长递增子序列

这才是「加强版」的部分。`O(n log n)` 的贪心解法**天然只给出长度，丢掉了路径**，
所以需要额外记一点东西来支持回溯。

要求：
- 输出一条长度为 LIS 的合法递增子序列
- **自己写一个校验函数** `is_valid(a, seq)`：验证它确实是 `a` 的子序列、且严格递增
- 在 `main()` 里对输出结果调用校验，打印 `[校验] 通过 / 不通过`

> ⚠️ 这一问最容易翻车的地方：回溯出来的下标**不满足原始顺序**，
> 或者长度对但中间的衔接断了。所以必须有校验函数，别靠肉眼看。

---

### 第 4 问（附加，不做也行）：耗时对比

用 `coding/tests/P01_LIS_big.in`（n = 100000）跑一下，把两种解法的耗时贴到下面的表格里。

**实测参考值**（g++ 16.2.0 -O2，RTX 5060 那台机器的 CPU）：

| 解法 | n=8000（随机） | n=100000（随机） |
|---|---|---|
| `O(n²)` DP（正确写法） | 9.5 ms | **9669 ms** |
| `O(n log n)` | 0.09 ms | **2.9 ms** |
| 倍数 | 100× | **≈3400×** |

关于 9.7 秒这个数有个细节值得注意：按 n² 从 n=8000 外推，n=100000 应该只要约 **1.5 秒**，
实测却是 9.7 秒——**额外慢了 6.5 倍**。原因是 n=8000 时 `a`(64 KB) + `dp`(32 KB) 能装进 L2，
n=100000 时变成 1.2 MB 超出 L2，内层循环每次都要去 L3/内存取数。

> 💡 **这节课的收益**：复杂度分析给的是"量级"，**常数因子（缓存、分支预测）可以再差一个数量级**。
> 所以「我算过是 O(n²) 所以应该够快」这种说法，必须用实测兜底。

**想稳稳看到超时**：把 n 加到 3×10⁵ 再跑（`O(n²)` 要几分钟）。

⚠️ 另外，**随机数据不是复杂度检验的试金石**。真正能卡出问题的是**有序/近似有序输入**
（例如单调递增 n=8000）——如果你把 `dp[i]` 定义成了「整条序列」而不是「长度」，
在那里会写一次拷贝一次，代价从 O(n²) 变成 O(n³)，**n=8000 就要 34 秒**。
两种输入都要测，只测随机数据会漏掉这类 bug。

## 八、提示（只给方向，不给答案）

- 第 1 问：`dp[i]` 应该表示「**以 a[i] 结尾**」的 LIS 长度，而不是「前 i 个元素」的 LIS 长度。
  这两个定义的区别想清楚，第 3 问的回溯才有立足点。
- 第 2 问：维护一个辅助数组，它的第 `k` 个位置存「所有长度为 `k+1` 的递增子序列中，**最小的那个结尾值**」。
  这个数组**天然有序**（这是能二分的前提，想想为什么），所以可以二分。
- 第 3 问：贪心解法会把历史覆盖掉。你需要额外记住「每个元素被放到了哪个位置」，
  或者「以每个元素结尾的 LIS 长度」——后者回溯更直观。
